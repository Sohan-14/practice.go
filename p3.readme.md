**P6 — Structured Logging & Request IDs**

Right now, our server uses `log.Printf`. It prints plain text. That works fine when you are the only person testing it. But in production, hundreds of requests happen every second, and multiple things happen inside each request.

Plain text logs quickly become an unreadable wall of text. You can't easily search them, parse them, or trace a single user's journey.

Structured logging (outputting JSON) and Request IDs fix this. Every log line will be a parseable object, and every request will have a unique ID so you can trace it from start to finish.

# **Module 1: Reproduce the Problem**

**Goal:** Watch plain text logs break down when multiple requests happen at the same time.

**Step 1 — Add some noisy logging**

In your current `main.go`, add a few `log.Printf` statements inside your handlers to simulate "doing work":

```go
func homeHandler(w http.ResponseWriter, r *http.Request) {
	log.Printf("Home handler: starting work")
	time.Sleep(100 * time.Millisecond) // simulate work
	log.Printf("Home handler: finished work")
	fmt.Fprintln(w, "Welcome to my Go HTTP server!")
}

func healthHandler(w http.ResponseWriter, r *http.Request) {
	log.Printf("Health handler: checking db")
	time.Sleep(50 * time.Millisecond) // simulate work
	log.Printf("Health handler: db is ok")
	writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
}
```

**Step 2 — Hammer the server**

```go
go run main.go
```

In another terminal, we will send multiple requests concurrently. We can use `curl` with `&` to run them in the background and `wait` for them to finish:

```go
curl -s http://localhost:8080/ > /dev/null &
curl -s http://localhost:8080/health > /dev/null &
curl -s http://localhost:8080/ > /dev/null &
curl -s http://localhost:8080/health > /dev/null &
wait
```

### Step 3 — Look at the server logs

Look at the terminal running your server. You will see something like this:

```go
Home handler: starting work
Health handler: checking db
Health handler: db is ok
Home handler: finished work
Home handler: starting work
Home handler: finished work
Health handler: checking db
Health handler: db is ok
```

### Why this is a problem

1. **Interleaving:** The logs from Request A and Request B are mixed together. Which "finished work" belongs to which "starting work"?
2. **No Identity:** There is no way to group these lines. If a user complains "my request failed", you can't find *their* specific log lines in a file with a million lines.

**The Solution: Structured Logging + Request IDs**

We need two things:

1. **Structured Logging:** Instead of `"Home handler: starting work"`, we output `{"level":"info", "msg":"starting work", "handler":"home", "request_id":"abc-123"}`. This is machine-readable (JSON).
2. **Request ID:** A unique string (like `req_8f3k2`) generated when the request enters the server, attached to *every* log line for that specific request.

When we combine them, the logs above become:

```json
{"level":"info", "msg":"starting work", "handler":"home", "request_id":"req_01"}
{"level":"info", "msg":"checking db", "handler":"health", "request_id":"req_02"}
{"level":"info", "msg":"db is ok", "handler":"health", "request_id":"req_02"}
{"level":"info", "msg":"finished work", "handler":"home", "request_id":"req_01"}
```

Even if they are interleaved in time, you can instantly filter and see exactly what `req_01` did, and exactly what `req_02` did.

# **Module 2: `log/slog` — Go's built-in structured logger**

Since Go 1.21, the standard library includes **`log/slog`** — a structured logger. No external dependencies needed

### The core idea

The old `log` package produces **plain text**:

```json
log.Printf("server started on port %d", 8080)
// 2026/11/03 10:15:23 server started on port 8080
```

`slog` produces **structured data** — key-value pairs, rendered as JSON:

```json
logger.Info("server started", "port", 8080)
// {"time":"...","level":"INFO","msg":"server started","port":8080}
```

That JSON object is **machine-readable**. Log aggregators (Loki, Datadog, ELK) can ingest it, and you can query it: *"give me every log where `port == 8080`."* You can't do that with a plain sentence.

**The three concepts**

| Concept | What it is |
| --- | --- |
| **Handler** | Decides the output format. `NewJSONHandler` → JSON. (`NewTextHandler` → `key=value` text.) |
| **Attributes** | The key-value pairs: `"port", 8080`. These are what make it structured. |
| **Levels** | Severity: `Debug` < `Info` < `Warn` < `Error`. Lets you filter verbosity. |

# **Module 3: Request IDs — giving every request a name**

Now we solve the identity problem.
Structured logs are useful, but without a shared ID, this still happens:

```json
request started
checking database
database failed
request finished
```

If 500 requests are running at the same time, which lines belong together?

A **request ID** fixes that.

A request ID is a unique value generated when a request enters the server:

```go
request_id = "b7e7c1d4e2f34a9c8d10a5f6c9e01234"
```

Then every log line for that request includes the same ID:

```json
{"level":"INFO","msg":"request started","request_id":"b7e7c1d4e2f34a9c8d10a5f6c9e01234","path":"/health"}
{"level":"INFO","msg":"checking database","request_id":"b7e7c1d4e2f34a9c8d10a5f6c9e01234"}
{"level":"INFO","msg":"request finished","request_id":"b7e7c1d4e2f34a9c8d10a5f6c9e01234","status":200}
```

Now you can filter logs by one field:

```go
request_id = b7e7c1d4e2f34a9c8d10a5f6c9e01234
```

**What makes a good request ID?**

A good request ID should be:

| Property | Why |
| --- | --- |
| Unique | Two requests should not share the same ID |
| Hard to collide | Even across multiple server instances |
| Cheap to generate | Every request gets one |
| Easy to print/search | Hex string is simple and readable |

We will use Go's standard library:

```go
crypto/rand
```

We will generate **16 random bytes** and encode them as hex.

16 bytes = 128 bits.

That gives us a huge ID space, so collisions are practically impossible for this use case.

**Example:**

```go
b := make([]byte, 16)
// Create a byte slice with space for 16 random bytes.
```

```go
rand.Read(b)
// Fill those bytes with cryptographically strong random data.
```

```go
hex.EncodeToString(b)
// Convert raw bytes into a readable hex string.
```

Raw bytes are not convenient to print. Hex gives us a clean string like:

```go
f41c7a1c98b04ef3913a7d8890b12c90
```

Now connect it to structured logs

```go
logger.Info("request started",
		"request_id", id,
		"method", "GET",
		"path", "/health",
	)
```

# Important production note

Later, we will put request IDs into middleware:

We may also return it to the client:

```go
X-Request-ID: f41c7a1c98b04ef3913a7d8890b12c90
```

Then if a user reports an error, they can give you that ID, and you can find the exact request in your logs.
But do not implement that yet. First we need to understand how to carry the ID through the request.

# **Module 4: Passing the Request ID with `context.Context`**

We can generate a request ID. We can log it. But there's a problem:

**Where does the ID live?**

The middleware generates it. But the handlers need it to log. And the handlers are called by the mux, which is called by the server — we don't control that call chain. We can't just pass the ID as a parameter:

```go
func healthHandler(w http.ResponseWriter, r *http.Request, requestID string)
```

That would break the handler signature. We'd have to change every handler, and the `http` package wouldn't know how to call them.

### The solution: `context.Context`

We've already seen `context.Context` in **P1 Module 3** — for deadlines and cancellation. But context has another superpower: **carrying request-scoped values**.

The pattern:

1. Middleware generates the request ID.
2. Middleware creates a **new context** with the ID attached.
3. Middleware creates a **new request** with that context.
4. Handlers extract the ID from the request's context.

### The API

```go
// Create a new context with a value
ctx := context.WithValue(parentCtx, key, value)

// Create a new request with that context
r = r.WithContext(ctx)

// Later, extract the value
value := r.Context().Value(key)
```

### Important: type-safe keys

If we use a plain string as the key:

```go
ctx := context.WithValue(ctx, "request_id", id)
```

Then anyone else in the program could accidentally use the same key `"request_id"` and overwrite or read our value. That's a collision bug.

The idiomatic Go solution: **define a custom type for the key**.

```go
type contextKey string

const requestIDKey contextKey = "request_id"
```

Now the key is a distinct type. Even if someone else uses the string `"request_id"`, it won't collide because their key is a `string`, not a `contextKey`.

# **Module 5: The Logging Middleware**

We will build a single middleware that:

1. Generates a unique request ID.
2. Attaches it to the request's context.
3. Logs the start of the request (method, path, ID).
4. Calls the next handler.
5. Logs the end of the request (ID, duration, and HTTP status code).

### The hidden challenge: capturing the status code

The standard `http.ResponseWriter` does not let you read the status code after it has been written. To log it, we must create a tiny **wrapper** that intercepts the `WriteHeader` call and saves the code.

### Step 1: The ResponseWriter Wrapper

Add this to your `main.go`:

```go
// responseWriter wraps http.ResponseWriter to capture the status code.
type responseWriter struct {
	http.ResponseWriter
	status int
}

func (rw *responseWriter) WriteHeader(code int) {
	rw.status = code
	rw.ResponseWriter.WriteHeader(code)
}
```

**Step 2: The Middleware**

Replace your old logging/recovery middlewares with this unified, production-grade version. (We will add recovery back in Module 6).

```go
func loggingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// 1. Generate request ID
		id, err := newRequestID()
		if err != nil {
			id = "unknown" // Fallback if random generation fails
		}

		// 2. Attach to context
		ctx := context.WithValue(r.Context(), requestIDKey, id)
		r = r.WithContext(ctx)

		// 3. Wrap the response writer to capture status code
		rw := &responseWriter{ResponseWriter: w, status: http.StatusOK}

		// 4. Log the start
		start := time.Now()
		logger.Info("request started",
			"request_id", id,
			"method", r.Method,
			"path", r.URL.Path,
		)

		// 5. Execute the actual handler
		next.ServeHTTP(rw, r)

		// 6. Log the completion
		duration := time.Since(start)
		logger.Info("request finished",
			"request_id", id,
			"status", rw.status,
			"duration_ms", duration.Milliseconds(),
		)
	})
}

func newRequestID() (string, error) {
	b := make([]byte, 16)

	if _, err := rand.Read(b); err != nil {
		return "", err
	}

	return hex.EncodeToString(b), nil
}
```

**Step 3: Update `main()` and Handlers**

Initialize the global logger at the top of `main()`:

```go
var logger *slog.Logger

func main() {
	// Initialize structured JSON logger
	logger = slog.New(slog.NewJSONHandler(os.Stdout, nil))

	mux := http.NewServeMux()
	mux.HandleFunc("GET /{$}", homeHandler)
	mux.HandleFunc("GET /health", healthHandler)
	mux.HandleFunc("GET /api/hello", helloHandler)

	server := &http.Server{
		Addr:         ":8080",
		Handler:      handler,
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 10 * time.Second,
	}
    // ... (keep the rest of your graceful shutdown code)
}
```

Update your handlers to extract the ID and log their own steps:

```go
func homeHandler(w http.ResponseWriter, r *http.Request) {
	id := r.Context().Value(requestIDKey).(string)
	logger.Info("home handler executing", "request_id", id)

	time.Sleep(100 * time.Millisecond) // simulate work

	fmt.Fprintln(w, "Welcome to my Go HTTP server!")
}

func healthHandler(w http.ResponseWriter, r *http.Request) {
	id := r.Context().Value(requestIDKey).(string)
	logger.Info("health check: querying db", "request_id", id)

	time.Sleep(50 * time.Millisecond) // simulate work

	writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
}

func helloHandler(w http.ResponseWriter, r *http.Request) {
	id := r.Context().Value(requestIDKey).(string)
	name := r.URL.Query().Get("name")
	if name == "" {
		name = "World"
	}
	logger.Info("hello handler executing", "request_id", id, "name", name)

	writeJSON(w, http.StatusOK, map[string]string{
		"message": fmt.Sprintf("Hello, %s!", name),
	})
}
```

### What you should see in the server logs

Instead of messy plain text, you will see clean, parseable JSON blocks. For `/health`, it will look like this:

```go
{"time":"2026-11-04T12:00:00Z","level":"INFO","msg":"request started","request_id":"a1b2c3d4...","method":"GET","path":"/health"}
{"time":"2026-11-04T12:00:00Z","level":"INFO","msg":"health check: querying db","request_id":"a1b2c3d4..."}
{"time":"2026-11-04T12:00:00Z","level":"INFO","msg":"request finished","request_id":"a1b2c3d4...","status":200,"duration_ms":51}
```

Notice the magic:

- Every line has the **same `request_id`**.
- The `duration_ms` tells you exactly how long the request took.
- The `status` tells you the HTTP response code.
- If you run multiple requests concurrently, you can still filter by `request_id` and see the exact sequence for *one* user.

# **Module 6: Polish — Return the ID to the client + stack recovery**

We have beautiful structured logs with request IDs. But there's one more piece for production: **let the client see their request ID too**.

### Why return the request ID?

When a user reports "I got an error," you ask: *"What was the request ID?"* They check their browser's network tab or API client, see the `X-Request-ID` header, and give it to you. You grep your logs and find the exact request instantly.

This is a standard production pattern. Many APIs return `X-Request-ID` in the response headers.

### Step 1: Add the response header

In your `loggingMiddleware`, add one line after you generate the ID:

```go
// NEW: Return the ID to the
w.Header().Set("X-Request-ID", id)
```

**Step 2: Stack the recovery middleware**

Remember we removed recovery in Module 5 to focus on logging? Now we add it back, as the **outermost** layer:

```go
  handler := recoverMiddleware(loggingMiddleware(mux))
```

Reading inside-out: `mux` → wrapped by `loggingMiddleware` → wrapped by `recoverMiddleware`.

So the request flow is:

```go
Request
  -> recoverMiddleware (defer registered)
     -> loggingMiddleware (generate ID, log start)
        -> mux -> your handler (logs its own steps)
     <- loggingMiddleware (log finish with duration/status)
  <- recoverMiddleware
Response (includes X-Request-ID header)
```

```go
go run main.go
```

```go
curl -i http://localhost:8080/health
```

You will see:

```go
HTTP/1.1 200 OK
Content-Type: application/json
X-Request-ID: a1b2c3d4e5f6...

```

## Restructured main.go:

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"log"
	"log/slog"
	"net/http"
	"os"
	"os/signal"
	"runtime/debug"
	"syscall"
	"time"
)

// responseWriter wraps http.ResponseWriter to capture the status code.
type responseWriter struct {
	http.ResponseWriter
	status int
}

func (rw *responseWriter) WriteHeader(code int) {
	rw.status = code
	rw.ResponseWriter.WriteHeader(code)
}

type contextKey string

const requestIDKey contextKey = "request_id"

var logger *slog.Logger

func main() {

	// Initialize structured JSON logger
	logger = slog.New(slog.NewJSONHandler(os.Stdout, nil))

	mux := http.NewServeMux()
	mux.HandleFunc("GET /{$}", homeHandler)
	mux.HandleFunc("GET /health", healthHandler)
	mux.HandleFunc("GET /api/hello", helloHandler)

	handler := recoverMiddleware(loggingMiddleware(mux))

	server := &http.Server{
		Addr:         ":8080",
		Handler:      handler,
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 10 * time.Second,
	}

	// serverErr carries fatal startup errors (e.g. port already in use)
	// from the server goroutine back to main.
	serverErr := make(chan error, 1)

	go func() {
		log.Println("server starting on :8080")
		// http.ErrServerClosed is the expected result of a graceful Shutdown,
		// so we only report real errors.
		if err := server.ListenAndServe(); err != nil && err != http.ErrServerClosed {
			serverErr <- err
		}
	}()

	// Wait for either a shutdown signal or a startup failure.
	sigChan := make(chan os.Signal, 1)
	signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)

	select {
	case err := <-serverErr:
		log.Fatalf("server failed to start: %v", err)
	case sig := <-sigChan:
		log.Printf("received signal %v, shutting down", sig)
	}

	// Graceful drain, capped at 10 seconds.
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	if err := server.Shutdown(ctx); err != nil {
		log.Printf("forced shutdown: %v", err)
		os.Exit(1)
	}

	log.Println("graceful shutdown complete")
}

	logger.Info("home handler executing", "request_id", id)

func writeJSON(w http.ResponseWriter, status int, data any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	json.NewEncoder(w).Encode(data)
}

func recoverMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("recovered from panic: %v\n%s", rec, debug.Stack())

				writeJSON(w, http.StatusInternalServerError, map[string]string{
					"error": "Internal Server Error",
				})
			}
		}()

		next.ServeHTTP(w, r)
	})
}

func loggingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// 1. Generate request ID
		id, err := newRequestID()
		if err != nil {
			id = "unknown" // Fallback if random generation fails
		}

		// NEW: Return the ID to the client
		w.Header().Set("X-Request-ID", id)

		// 2. Attach to context
		ctx := context.WithValue(r.Context(), requestIDKey, id)
		r = r.WithContext(ctx)

		// 3. Wrap the response writer to capture status code
		rw := &responseWriter{ResponseWriter: w, status: http.StatusOK}

		// 4. Log the start
		start := time.Now()
		logger.Info("request started",
			"request_id", id,
			"method", r.Method,
			"path", r.URL.Path,
		)

		// 5. Execute the actual handler
		next.ServeHTTP(rw, r)

		// 6. Log the completion
		duration := time.Since(start)
		logger.Info("request finished",
			"request_id", id,
			"status", rw.status,
			"duration_ms", duration.Milliseconds(),
		)
	})
}
```
