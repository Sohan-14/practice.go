# **Module 1: Reproduce the Problem**

**Goal:** Observe what happens when an endpoint is flooded with requests, proving that we currently have no defense against abuse.

### Step 1: Identify the target

We will use your existing `/api/hello` endpoint. Right now, it does a tiny bit of work (formatting a string) and returns a response. It has no limits.

### Step 2: Flood the endpoint

We will use a tool called `hey` or `wrk` if you have it, but to keep it simple and dependency-free, we will use a simple bash loop with `curl` running in the background.

Open your terminal and run this command. It will fire 100 requests as fast as possible:

Objective: See how many succeed and how long it takes.

```go

```

**Step 3: Observe the result**

You will likely see output similar to this:

```go
    100 200

user    0m0.050s
sys     0m0.100s
```

**What this means:**

- `100 200`: All 100 requests succeeded with a `200 OK` status.
- `real 0m0.150s`: It took a fraction of a second. The server happily processed all of them.

### Step 4: The danger

Now imagine that loop is not `100` requests, but `100,000` requests per second from a botnet, or a buggy client stuck in an infinite loop.

Because we have no rate limiting:

1. The server will consume CPU and memory trying to process every single request.
2. TimeLegitimate users will experience severe slowdowns or timeouts (Denial of Service).
3. If this endpoint interacted with a database, we would exhaust the database connection pool.

### The Solution

We need a mechanism that says: *"This specific client (identified by IP address) is only allowed to make 10 requests per minute. If they exceed that, reject the request immediately with a `429 Too Many Requests` status, before it even reaches the handler."*

# **Module 2: The Token Bucket Algorithm**

Before we write any Go code, we need to understand the logic. Rate limiting is not just "count requests and block after N". The industry standard is the **Token Bucket** algorithm.

### The Concept

Imagine a physical bucket that holds tokens.

1. **Capacity**: The bucket can hold a maximum number of tokens (e.g., 10). This is your **burst limit**.
2. **Refill Rate**: Tokens are added to the bucket at a steady rate (e.g., 1 token per second). This is your **sustained rate**.
3. **The Rule**: Every incoming request must take exactly 1 token from the bucket to be processed.
    - If the bucket has >= 1 token, the request is **allowed**, and the token count decreases by 1.
    - If the bucket has 0 tokens, the request is **rejected** (rate limited).

### Why this is better than a simple counter

A naive approach is: "Allow 10 requests per minute, then block for the rest of the minute."
This is bad for user experience. If a user makes 10 requests in the first second, they are blocked for 59 seconds, even though the average rate is fine.

The Token Bucket allows for **natural bursts**. If the bucket is full (10 tokens), a user can fire 10 requests instantly. As long as they slow down afterward, the bucket refills, and they can continue making requests at the sustained rate (1 per second) without ever hitting the limit again.

### Walkthrough Example

Let's trace a bucket with:

- **Capacity**: 3 tokens
- **Refill Rate**: 1 token per second

| Time | Event | Tokens in Bucket | Result |
| --- | --- | --- | --- |
| 0.0s | Bucket starts full | 3 | - |
| 0.1s | Request 1 arrives | 2 | **Allowed** |
| 0.2s | Request 2 arrives | 1 | **Allowed** |
| 0.3s | Request 3 arrives | 0 | **Allowed** (Burst exhausted) |
| 0.4s | Request 4 arrives | 0 | **Rejected** (No tokens) |
| 0.5s | Request 5 arrives | 0 | **Rejected** |
| 1.1s | 1 second has passed, 1 token refills | 1 | - |
| 1.2s | Request 6 arrives | 0 | **Allowed** |

Notice how Requests 4 and 5 were rejected, but as soon as the bucket refilled at 1.1s, Request 6 was allowed. This perfectly models "3 requests per second, with a burst capacity of 3".

### The Two Key Variables

When we build this in code, every client (identified by IP address) will have their own virtual bucket. We need to track two numbers per client:

1. `tokens`: The current number of tokens available (float, so we can handle fractional refills).
2. `last_refill`: The timestamp of the last time we calculated the refill.

When a request arrives, we do this math:

1. Calculate time elapsed since `last_refill`.
2. Add `(elapsed_time * refill_rate)` to `tokens`.
3. Cap `tokens` at `capacity` (the bucket can't overflow).
4. Update `last_refill` to now.
5. If `tokens >= 1`, subtract 1 and allow. Otherwise, reject.

# **Module 3: In-Memory Rate Limiter**

Now we translate the Token Bucket math into Go code.

Because HTTP handlers run concurrently (each request in its own goroutine), multiple requests from the same client might hit the rate limiter at the exact same millisecond. If we just use a standard Go `map`, concurrent reads and writes will cause a **fatal panic** (`concurrent map read and map write`).

To fix this, we must use a **`sync.Mutex`** (mutual exclusion lock) to ensure only one goroutine can check or update a client's bucket at a time.

### Step 1: Define the structs

Add this to your `main.go` (or a separate file like `ratelimit.go`):

```go
// clientBucket holds the state for a single client's token bucket.
type clientBucket struct {
	tokens     float64
	lastRefill time.Time
}

// RateLimiter manages token buckets for multiple clients.
type RateLimiter struct {
	mu         sync.Mutex          // Protects the clients map
	clients    map[string]*clientBucket
	capacity   float64             // Max tokens (burst limit)
	refillRate float64             // Tokens added per second
}
```

**Step 2: The constructor**

```go
// NewRateLimiter creates a rate limiter with the given capacity and refill rate.
func NewRateLimiter(capacity float64, refillRate float64) *RateLimiter {
	return &RateLimiter{
		clients:    make(map[string]*clientBucket),
		capacity:   capacity,
		refillRate: refillRate,
	}
}
```

**Step 3: The `Allow` method (The core logic)**

```go
// Allow checks if a request from the given clientID should be allowed.
func (rl *RateLimiter) Allow(clientID string) bool {
	rl.mu.Lock()         // 1. Lock the mutex before touching the map
	defer rl.mu.Unlock() // 2. Ensure it gets unlocked when we return

	bucket, exists := rl.clients[clientID]
	now := time.Now()

	if !exists {
		// New client: start with a full bucket
		bucket = &clientBucket{
			tokens:     rl.capacity,
			lastRefill: now,
		}
		rl.clients[clientID] = bucket
	} else {
		// Existing client: calculate elapsed time and refill tokens
		elapsed := now.Sub(bucket.lastRefill).Seconds()
		bucket.tokens += elapsed * rl.refillRate

		// Cap the tokens at the maximum capacity (bucket can't overflow)
		if bucket.tokens > rl.capacity {
			bucket.tokens = rl.capacity
		}

		// Update the last refill time to now
		bucket.lastRefill = now
	}

	// 3. Check if we have at least 1 token to spend
	if bucket.tokens >= 1.0 {
		bucket.tokens -= 1.0 // Spend the token
		return true          // Request allowed
	}

	return false // Request rejected (rate limited)
}
```

### Line-by-line breakdown

1. `rl.mu.Lock()` / `defer rl.mu.Unlock()`: This guarantees that if 100 requests from the same IP arrive simultaneously, they are processed one by one. No race conditions.
2. `!exists`: If it's the client's first request, we give them a full bucket (`rl.capacity`).
3. `elapsed := now.Sub(bucket.lastRefill).Seconds()`: How many seconds have passed since the last time we checked this client?
4. `bucket.tokens += elapsed * rl.refillRate`: Add the newly earned tokens. (e.g., if 0.5 seconds passed and rate is 2/sec, add 1.0 token).
5. `if bucket.tokens > rl.capacity`: Prevent the bucket from holding more than its max size.
6. `if bucket.tokens >= 1.0`: The gatekeeper. If we have a token, spend it (`= 1.0`) and return `true`. Otherwise, return `false`.

# **Module 4: The Rate Limiting Middleware**

Now we wire the rate limiter into the HTTP request lifecycle. This is where we turn the `RateLimiter.Allow()` method into a middleware that sits in front of your handlers.

### Step 1: Extract the client IP

Every HTTP request has a `RemoteAddr` field that contains the client's IP address and port (e.g., `"192.168.1.100:54321"`). We need to strip the port to get just the IP.

Add this helper function:

```go
func getClientIP(r *http.Request) string {
	// RemoteAddr is in the format "IP:port"
	ip, _, err := net.SplitHostPort(r.RemoteAddr)
	if err != nil {
		// If SplitHostPort fails, just return RemoteAddr as-is
		return r.RemoteAddr
	}
	return ip
}
```

**Step 2: Build the middleware**

```go
// rateLimitMiddleware wraps a handler and enforces rate limiting per client IP.
func rateLimitMiddleware(rl *RateLimiter) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			clientIP := getClientIP(r)

			if !rl.Allow(clientIP) {
				// Rate limit exceeded
				w.Header().Set("Content-Type", "application/json")
				w.WriteHeader(http.StatusTooManyRequests) // 429
				json.NewEncoder(w).Encode(map[string]string{
					"error":   "rate_limit_exceeded",
					"message": "Too many requests. Please try again later.",
				})
				return
			}

			// Rate limit not exceeded, proceed to the next handler
			next.ServeHTTP(w, r)
		})
	}
}
```

### Line-by-line breakdown

1. `func rateLimitMiddleware(rl *RateLimiter) func(http.Handler) http.Handler`: This is a middleware factory. It takes a `RateLimiter` instance and returns a middleware function.
2. `clientIP := getClientIP(r)`: Extract the client's IP address.
3. `if !rl.Allow(clientIP)`: Check if the client has exceeded their rate limit.
4. `w.WriteHeader(http.StatusTooManyRequests)`: Set the HTTP status code to `429`.
5. `json.NewEncoder(w).Encode(...)`: Return a structured JSON error (consistent with our validation errors from P13).
6. `return`: Stop processing. Don't call `next.ServeHTTP`.
7. `next.ServeHTTP(w, r)`: If the rate limit is not exceeded, proceed to the actual handler.

**Step 3: Wire it into `main()`**

# **Module 5: Proper 429 Responses with `Retry-After`**

Right now, when a client gets rate-limited, they see:

```go
{
	"error":"rate_limit_exceeded",
	"message":"Too many requests. Please try again later."
}
```

But they have no idea **how long to wait**. Should they retry in 1 second? 1 minute? 1 hour? Without this information, clients either:

- Retry immediately (making the problem worse)
- Give up entirely (bad user experience)
- Guess randomly (unreliable)

The HTTP standard provides the **`Retry-After`** header for exactly this purpose.

### The `Retry-After` header

When a server returns `429 Too Many Requests`, it should include:

```go
Retry-After: 2
```

### Step 1: Modify the rate limiter to calculate retry time

We need to change the `Allow` method to return not just `true/false`, but also **how long to wait** if the request is rejected.

Update your `RateLimiter.Allow` method:

```go
// Allow checks if a request from the given clientID should be allowed.
// Returns (allowed, retryAfter) where retryAfter is how long to wait if not allowed.
func (rl *RateLimiter) Allow(clientID string) (bool, time.Duration) {
	rl.mu.Lock()
	defer rl.mu.Unlock()

	bucket, exists := rl.clients[clientID]
	now := time.Now()

	if !exists {
		bucket = &clientBucket{
			tokens:     rl.capacity,
			lastRefill: now,
		}
		rl.clients[clientID] = bucket
	} else {
		elapsed := now.Sub(bucket.lastRefill).Seconds()
		bucket.tokens += elapsed * rl.refillRate

		if bucket.tokens > rl.capacity {
			bucket.tokens = rl.capacity
		}

		bucket.lastRefill = now
	}

	if bucket.tokens >= 1.0 {
		bucket.tokens -= 1.0
		return true, 0 // Allowed, no retry needed
	}

	// Not allowed: calculate how long until we have 1 token
	// We need (1.0 - current_tokens) more tokens
	// At refillRate tokens per second, that takes:
	tokensNeeded := 1.0 - bucket.tokens
	retryAfterSeconds := tokensNeeded / rl.refillRate
	retryAfter := time.Duration(retryAfterSeconds * float64(time.Second))

	return false, retryAfter
}
```

### The math

If the bucket has `0.3` tokens and the refill rate is `2.0` tokens/second:

- We need `1.0 - 0.3 = 0.7` more tokens
- At `2.0` tokens/sec, that takes `0.7 / 2.0 = 0.35` seconds
- Convert to `time.Duration`: `0.35 * time.Second = 350ms`

**Step 2: Update the middleware to include the header**

```go
func rateLimitMiddleware(rl *RateLimiter) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			clientIP := getClientIP(r)

			allowed, retryAfter := rl.Allow(clientIP)

			if !allowed {
				// Set the Retry-After header (in seconds, rounded up)
				retryAfterSeconds := int(math.Ceil(retryAfter.Seconds()))
				w.Header().Set("Retry-After", strconv.Itoa(retryAfterSeconds))

				// Return structured error
				w.Header().Set("Content-Type", "application/json")
				w.WriteHeader(http.StatusTooManyRequests)
				json.NewEncoder(w).Encode(map[string]string{
					"error":       "rate_limit_exceeded",
					"message":     "Too many requests. Please try again later.",
					"retry_after": strconv.Itoa(retryAfterSeconds),
				})
				return
			}

			next.ServeHTTP(w, r)
		})
	}
}
```

### Line-by-line

1. `allowed, retryAfter := rl.Allow(clientIP)`: Get both the decision and the retry time.
2. `math.Ceil(retryAfter.Seconds())`: Round up to the nearest whole second (HTTP standard expects integers).
3. `w.Header().Set("Retry-After", ...)`: Set the standard HTTP header.
4. `"retry_after": ...` in the JSON body: Also include it in the response body for convenience (some clients prefer parsing JSON over headers).

# **Module 6: Polish — Memory Leaks & Production Considerations**

The rate limiter works, but there's a serious production issue: **memory leaks**.

### The Problem

Every unique IP address that hits your server creates an entry in the `clients` map:

```go
clients map[string]*clientBucket
```

In a real production environment:

- You might serve millions of unique IP addresses per day
- Each entry takes ~100 bytes (IP string + struct + map overhead)
- 1 million entries = ~100 MB of memory
- 10 million entries = ~1 GB of memory

And we **never clean them up**. Old entries sit in the map forever, even if that IP hasn't made a request in days.

**The Solution: Periodic Cleanup**

We need a background goroutine that periodically scans the map and removes entries that haven't been used recently.

### Step 1: Add a cleanup method

Add this method to your `RateLimiter`:

```go

// Cleanup removes entries that haven't been used for longer than maxAge.
func (rl *RateLimiter) Cleanup(maxAge time.Duration) {
	rl.mu.Lock()
	defer rl.mu.Unlock()

	now := time.Now()
	for clientID, bucket := range rl.clients {
		if now.Sub(bucket.lastRefill) > maxAge {
			delete(rl.clients, clientID)
		}
	}
}
```

This iterates through all entries and deletes any where `lastRefill` is older than `maxAge`.

### Step 2: Start a background cleanup goroutine

Add a method that starts the cleanup loop:

```go
// StartCleanup launches a background goroutine that periodically cleans up stale entries.
func (rl *RateLimiter) StartCleanup(interval, maxAge time.Duration) {
	go func() {
		for {
			time.Sleep(interval)
			rl.Cleanup(maxAge)
		}
	}()
}
```

This runs forever in the background, sleeping for `interval`, then cleaning up entries older than `maxAge`.

**Step 3: Wire it into `main()`**

```go

func writeJSON(w http.ResponseWriter, status int, data any) {

func recoverMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("recovered from panic: %v\n%s", rec, debug.Stack())

				writeJSON(w, http.StatusInternalServerError, map[string]string{
					"error": "Internal Server Error",
				})
			}
		}()

		next.ServeHTTP(w, r)
	})
}

func loggingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// 1. Generate request ID
		id, err := newRequestID()
		if err != nil {
			id = "unknown" // Fallback if random generation fails
		}

		// NEW: Return the ID to the client
		w.Header().Set("X-Request-ID", id)

		// 2. Attach to context
		ctx := context.WithValue(r.Context(), requestIDKey, id)
		r = r.WithContext(ctx)

		// 3. Wrap the response writer to capture status code
		rw := &responseWriter{ResponseWriter: w, status: http.StatusOK}

		// 4. Log the start
		start := time.Now()
		logger.Info("request started",
			"request_id", id,
			"method", r.Method,
			"path", r.URL.Path,
		)

		// 5. Execute the actual handler
		next.ServeHTTP(rw, r)

		// 6. Log the completion
		duration := time.Since(start)
		logger.Info("request finished",
			"request_id", id,
			"status", rw.status,
			"duration_ms", duration.Milliseconds(),
		)
	})
}

func newRequestID() (string, error) {
	b := make([]byte, 16)

	if _, err := rand.Read(b); err != nil {
		return "", err
	}

	return hex.EncodeToString(b), nil
}
func createUserHandler(w http.ResponseWriter, r *http.Request) {
	const maxBodySize = 1 << 20 // 1 MB
	r.Body = http.MaxBytesReader(w, r.Body, maxBodySize)

	var user struct {
		Name  string `json:"name"`
		Email string `json:"email"`
	}

	decoder := json.NewDecoder(r.Body)
	decoder.DisallowUnknownFields()

	if err := decoder.Decode(&user); err != nil {
		writeJSON(w, http.StatusBadRequest, errorResponse{
			Error:   "invalid_json",
			Message: "Request body contains unknown fields",
		})
		return
	}

	// Collect all validation errors
	var errors []validationError

	if user.Name == "" {
		errors = append(errors, validationError{
			Field:   "name",
			Message: "Name is required",
		})
	} else if len(user.Name) < 2 {
		errors = append(errors, validationError{
			Field:   "name",
			Message: "Name must be at least 2 characters",
		})
	}

	if user.Email == "" {
		errors = append(errors, validationError{
			Field:   "email",
			Message: "Email is required",
		})
	} else if !isValidEmail(user.Email) {
		errors = append(errors, validationError{
			Field:   "email",
			Message: "Email format is invalid",
		})
	}

	// If there are validation errors, return them
	if len(errors) > 0 {
		writeJSON(w, http.StatusBadRequest, errorResponse{
			Error:   "validation_failed",
			Message: "Request validation failed",
			Details: errors,
		})
		return
	}

	// Success case
	log.Printf("created user: %s (%s)", user.Name, user.Email)
	writeJSON(w, http.StatusCreated, map[string]string{
		"message": "User created",
		"name":    user.Name,
		"email":   user.Email,
	})
}
func isValidEmail(email string) bool {
	return strings.Contains(email, "@")
}

func searchHandler(w http.ResponseWriter, r *http.Request) {
	query := r.URL.Query()

	// Collect validation errors
	var errors []validationError

	// Required parameter: q
	q := query.Get("q")
	if q == "" {
		errors = append(errors, validationError{
			Field:   "q",
			Message: "Search query is required",
		})
	}

	// Optional parameter: page (default 1, must be positive)
	pageStr := query.Get("page")
	page := 1
	if pageStr != "" {
		p, err := strconv.Atoi(pageStr)
		if err != nil {
			errors = append(errors, validationError{
				Field:   "page",
				Message: "Page must be a number",
			})
		} else if p < 1 {
			errors = append(errors, validationError{
				Field:   "page",
				Message: "Page must be at least 1",
			})
		} else {
			page = p
		}
	}

	// Optional parameter: limit (default 10, must be 1-100)
	limitStr := query.Get("limit")
	limit := 10
	if limitStr != "" {
		l, err := strconv.Atoi(limitStr)
		if err != nil {
			errors = append(errors, validationError{
				Field:   "limit",
				Message: "Limit must be a number",
			})
		} else if l < 1 || l > 100 {
			errors = append(errors, validationError{
				Field:   "limit",
				Message: "Limit must be between 1 and 100",
			})
		} else {
			limit = l
		}
	}

	// Return validation errors if any
	if len(errors) > 0 {
		writeJSON(w, http.StatusBadRequest, errorResponse{
			Error:   "validation_failed",
			Message: "Query parameter validation failed",
			Details: errors,
		})
		return
	}

	// Success: return the parsed parameters
	writeJSON(w, http.StatusOK, map[string]any{
		"query": q,
		"page":  page,
		"limit": limit,
	})
}
func rateLimitMiddleware(rl *RateLimiter) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			clientIP := getClientIP(r)

			allowed, retryAfter := rl.Allow(clientIP)

			if !allowed {
				// Set the Retry-After header (in seconds, rounded up)
				retryAfterSeconds := int(math.Ceil(retryAfter.Seconds()))
				w.Header().Set("Retry-After", strconv.Itoa(retryAfterSeconds))

				// Return structured error
				w.Header().Set("Content-Type", "application/json")
				w.WriteHeader(http.StatusTooManyRequests)
				json.NewEncoder(w).Encode(map[string]string{
					"error":       "rate_limit_exceeded",
					"message":     "Too many requests. Please try again later.",
					"retry_after": strconv.Itoa(retryAfterSeconds),
				})
				return
			}

			next.ServeHTTP(w, r)
		})
	}
}

func getClientIP(r *http.Request) string {
	// RemoteAddr is in the format "IP:port"
	ip, _, err := net.SplitHostPort(r.RemoteAddr)
	if err != nil {
		// If SplitHostPort fails, just return RemoteAddr as-is
		return r.RemoteAddr
	}
	return ip
}
```
