# **Module 1: Reproduce the Problem**

## The Problems We've Identified

1. **No validation of required fields** — we accepted a user with no email.
2. **No size limit** — a 100MB payload can exhaust memory.
3. **Generic error messages** — "Invalid JSON" doesn't tell the client *what* was wrong.
4. **No validation of business rules** — e.g., is the email format valid?

# **Module 2: Limit Request Body Size**

Now we fix the memory exhaustion vulnerability. The solution is **`http.MaxBytesReader`** — it wraps the request body and rejects anything larger than a specified limit.

### The concept

`http.MaxBytesReader` is a simple wrapper:

```go
r.Body = http.MaxBytesReader(w, r.Body, maxSize)
```

It takes three arguments:

- `w` — the response writer (to send the error response)
- `r.Body` — the original request body
- `maxSize` — the maximum allowed size in bytes

After wrapping, if the client tries to read more than `maxSize`, the decoder will return an error.

### Why this works

The JSON decoder reads from `r.Body` incrementally. When it hits the limit, `MaxBytesReader` returns an error instead of reading more data. The decoder never sees the full payload, so memory is never exhausted.

### Apply it to the handler

Update your `createUserHandler`:

```go
func createUserHandler(w http.ResponseWriter, r *http.Request) {
	// NEW: Limit request body to 1MB
	const maxBodySize = 1 << 20 // 1 MB
	r.Body = http.MaxBytesReader(w, r.Body, maxBodySize)

	var user struct {
		Name  string `json:"name"`
		Email string `json:"email"`
	}

	if err := json.NewDecoder(r.Body).Decode(&user); err != nil {
		http.Error(w, "Invalid JSON", http.StatusBadRequest)
		return
	}

	log.Printf("created user: %s (%s)", user.Name, user.Email)
	writeJSON(w, http.StatusCreated, map[string]string{
		"message": "User created",
		"name":    user.Name,
		"email":   user.Email,
	})
}
```

The key line:

```go
r.Body = http.MaxBytesReader(w, r.Body, maxBodySize)
```

This wraps the body **before** the decoder reads it.

# **Module 3: Validate JSON Input**

Now we fix the validation gap. Right now, we accept a user with no email, or with an invalid email format. We need to check the data **after** decoding it.

### The concept

Validation happens in three layers:

1. **Decode** — is it valid JSON? (we already do this)
2. **Required fields** — are all mandatory fields present?
3. **Business rules** — do the values make sense? (email format, name length, etc.)

We'll add validation **after** the decode succeeds but **before** we use the data.

### Step 1: Validate required fields

Update your handler to check that both `name` and `email` are non-empty:

```go
func createUserHandler(w http.ResponseWriter, r *http.Request) {
	const maxBodySize = 1 << 20 // 1 MB
	r.Body = http.MaxBytesReader(w, r.Body, maxBodySize)

	var user struct {
		Name  string `json:"name"`
		Email string `json:"email"`
	}

	if err := json.NewDecoder(r.Body).Decode(&user); err != nil {
		http.Error(w, "Invalid JSON", http.StatusBadRequest)
		return
	}

	// NEW: Validate required fields
	if user.Name == "" || user.Email == "" {
		http.Error(w, "Name and email are required", http.StatusBadRequest)
		return
	}

	log.Printf("created user: %s (%s)", user.Name, user.Email)
	writeJSON(w, http.StatusCreated, map[string]string{
		"message": "User created",
		"name":    user.Name,
		"email":   user.Email,
	})
}
```

The key addition:

```go
if user.Name == "" || user.Email == "" {
	http.Error(w, "Name and email are required", http.StatusBadRequest)
	return
}
```

**Step 2: Validate email format**

A simple check: does the email contain an `@` symbol? (Real production code would use a more robust regex or validation library, but this is sufficient for learning.)

```go
func isValidEmail(email string) bool {
	return strings.Contains(email, "@")
}
```

Then update the validation:

```go
	// Validate required fields
	if user.Name == "" || user.Email == "" {
		http.Error(w, "Name and email are required", http.StatusBadRequest)
		return
	}

	// NEW: Validate email format
	if !isValidEmail(user.Email) {
		http.Error(w, "Invalid email format", http.StatusBadRequest)
		return
	}
```

**Step 3: Add business rule validation**

Let's add one more rule: the name must be at least 2 characters long.

```go
	// Validate name length
	if len(user.Name) < 2 {
		http.Error(w, "Name must be at least 2 characters", http.StatusBadRequest)
		return
	}
```

### The validation order matters

Notice the order:

1. Decode JSON (catch syntax errors)
2. Check required fields (catch missing data)
3. Check formats (catch invalid data)
4. Check business rules (catch nonsensical data)

This order gives the most useful error messages. If we checked email format before checking if email was present, we'd get "Invalid email format" for an empty string, which is confusing.

**The limitation: generic error messages**

Right now, each validation failure returns a different error message, but they're all plain text. In Module 4, we'll make them structured JSON so clients can parse them programmatically.

For now, the important thing is that **invalid data is rejected** before it reaches your business logic.

# **Module 4: Structured Validation Errors**

Right now, our validation errors are plain text:

```go
Name and email are required
```

That's fine for humans reading curl output, but **terrible for API clients**. A JavaScript frontend, mobile app, or another service needs to:

- Parse the error programmatically
- Show specific messages to users
- Handle different error types differently

Plain text forces clients to do string matching, which is fragile and breaks when you change the message.

### The solution: structured JSON errors

Instead of:

```go
Name and email are required
```

We return:

```go
{
  "error": "validation_failed",
  "message": "Request validation failed",
  "details": [
    {"field": "name", "message": "Name is required"},
    {"field": "email", "message": "Email is required"}
  ]
}
```

Now the client can:

- Check `error == "validation_failed"` to know it's a validation issue
- Loop through `details` to show each error next to the relevant form field
- Parse it with standard JSON libraries

**Step 1: Define the error response structure**

Add this to your `main.go`:

```go
type validationError struct {
	Field   string `json:"field"`
	Message string `json:"message"`
}

type errorResponse struct {
	Error   string            `json:"error"`
	Message string            `json:"message"`
	Details []validationError `json:"details,omitempty"`
}
```

**Step 2: Refactor the handler to collect all errors**

Instead of returning on the first validation failure, collect **all** errors and return them together:

```go
func createUserHandler(w http.ResponseWriter, r *http.Request) {
	const maxBodySize = 1 << 20 // 1 MB
	r.Body = http.MaxBytesReader(w, r.Body, maxBodySize)

	var user struct {
		Name  string `json:"name"`
		Email string `json:"email"`
	}

	if err := json.NewDecoder(r.Body).Decode(&user); err != nil {
		writeJSON(w, http.StatusBadRequest, errorResponse{
			Error:   "invalid_json",
			Message: "Request body is not valid JSON",
		})
		return
	}

	// Collect all validation errors
	var errors []validationError

	if user.Name == "" {
		errors = append(errors, validationError{
			Field:   "name",
			Message: "Name is required",
		})
	} else if len(user.Name) < 2 {
		errors = append(errors, validationError{
			Field:   "name",
			Message: "Name must be at least 2 characters",
		})
	}

	if user.Email == "" {
		errors = append(errors, validationError{
			Field:   "email",
			Message: "Email is required",
		})
	} else if !isValidEmail(user.Email) {
		errors = append(errors, validationError{
			Field:   "email",
			Message: "Email format is invalid",
		})
	}

	// If there are validation errors, return them
	if len(errors) > 0 {
		writeJSON(w, http.StatusBadRequest, errorResponse{
			Error:   "validation_failed",
			Message: "Request validation failed",
			Details: errors,
		})
		return
	}

	// Success case
	log.Printf("created user: %s (%s)", user.Name, user.Email)
	writeJSON(w, http.StatusCreated, map[string]string{
		"message": "User created",
		"name":    user.Name,
		"email":   user.Email,
	})
}
```

### Why this pattern matters

1. **Consistency** — every validation error has the same structure. Clients can write one parser for all endpoints.
2. **Multiple errors** — the client gets all problems at once, not just the first one. Better UX.
3. **Machine-readable** — the `error` field is a stable identifier (`validation_failed`, `invalid_json`), not a human string that might change.
4. **Field-level errors** — the `field` in each detail lets the client highlight the specific form field that has an error.

### The limitation: repetition

If you have 10 endpoints that accept user input, you'll copy-paste this validation logic 10 times. That's not ideal. In a real production codebase, you'd:

- Use a validation library (like `go-playground/validator`)
- Extract validation into reusable functions
- Use struct tags to declare rules

But for learning, doing it manually first is valuable — you understand exactly what's happening.

# **Module 5: Query Parameter Validation**

We've validated the request **body**. But query parameters also accept user input, and they need the same treatment.

### The current state

Your `/api/hello` endpoint accepts a `name` query parameter:

```go
func helloHandler(w http.ResponseWriter, r *http.Request) {
	name := r.URL.Query().Get("name")
	if name == "" {
		name = "World"
	}
	writeJSON(w, http.StatusOK, map[string]string{
		"message": fmt.Sprintf("Hello, %s!", name),
	})
}
```

This works, but it has gaps:

- What if `name` is empty? We default to "World" — is that always correct?
- What if we add more parameters (e.g., `age`, `count`)? They're all strings, but we might need numbers.
- No validation errors are returned — we just silently use defaults.

**The scenario: add a `/api/search` endpoint**

Let's build a search endpoint that accepts:

- `q` (required) — the search query
- `page` (optional, default 1) — must be a positive integer
- `limit` (optional, default 10) — must be between 1 and 100

This demonstrates query parameter validation with type conversion and business rules.

**Step 1: Add the route**

```go
mux.HandleFunc("GET /api/search", searchHandler)
```

**Step 2: Build the handler with validation**

```go
func searchHandler(w http.ResponseWriter, r *http.Request) {
	query := r.URL.Query()

	// Collect validation errors
	var errors []validationError

	// Required parameter: q
	q := query.Get("q")
	if q == "" {
		errors = append(errors, validationError{
			Field:   "q",
			Message: "Search query is required",
		})
	}

	// Optional parameter: page (default 1, must be positive)
	pageStr := query.Get("page")
	page := 1
	if pageStr != "" {
		p, err := strconv.Atoi(pageStr)
		if err != nil {
			errors = append(errors, validationError{
				Field:   "page",
				Message: "Page must be a number",
			})
		} else if p < 1 {
			errors = append(errors, validationError{
				Field:   "page",
				Message: "Page must be at least 1",
			})
		} else {
			page = p
		}
	}

	// Optional parameter: limit (default 10, must be 1-100)
	limitStr := query.Get("limit")
	limit := 10
	if limitStr != "" {
		l, err := strconv.Atoi(limitStr)
		if err != nil {
			errors = append(errors, validationError{
				Field:   "limit",
				Message: "Limit must be a number",
			})
		} else if l < 1 || l > 100 {
			errors = append(errors, validationError{
				Field:   "limit",
				Message: "Limit must be between 1 and 100",
			})
		} else {
			limit = l
		}
	}

	// Return validation errors if any
	if len(errors) > 0 {
		writeJSON(w, http.StatusBadRequest, errorResponse{
			Error:   "validation_failed",
			Message: "Query parameter validation failed",
			Details: errors,
		})
		return
	}

	// Success: return the parsed parameters
	writeJSON(w, http.StatusOK, map[string]any{
		"query": q,
		"page":  page,
		"limit": limit,
	})
}
```

# **Module 6: Polish — Handling Unknown Fields**

We've validated required fields, types, ranges, and formats. But there's one more edge case: **what if the client sends fields we don't expect?**

### The default behavior

Right now, if a client sends:

```go
{
  "name": "Alice",
  "email": "alice@example.com",
  "age": 30,
  "favorite_color": "blue"
}
```

Go's JSON decoder **silently ignores** `age` and `favorite_color` because they're not in our struct. The request succeeds.

lThis is usually fine — it's lenient and forward-compatible. But sometimes you want **strict validation**: reject requests with unknown fields to catch client bugs (typos, outdated API versions).

**Option 1: Strict mode (reject unknown fields)**

Add this line after creating the decoder:

```go
decoder := json.NewDecoder(r.Body)
decoder.DisallowUnknownFields()

if err := decoder.Decode(&user); err != nil {
	writeJSON(w, http.StatusBadRequest, errorResponse{
		Error:   "invalid_json",
		Message: "Request body contains unknown fields",
	})
	return
}
```

Now if the client sends `age` or `favorite_color`, they get:

```go
{
  "error": "invalid_json",
  "message": "Request body contains unknown fields"
}
```

**When to use strict mode:**

- Internal APIs where you control all clients
- Catching typos during development
- Preventing accidental misuse

### Option 2: Lenient mode (ignore unknown fields) — the default

This is what we already have. Unknown fields are silently ignored.

**When to use lenient mode:**

- Public APIs with many clients
- Forward compatibility (clients can send extra fields without breaking)
- Gradual API evolution

### The recommendation

For most production APIs, **lenient mode is better**. Strict mode causes more problems than it solves:

- Clients break when you add new fields (even if they don't use them)
- Different API versions need different validation
- Third-party integrations become fragile

Use strict mode only for internal APIs or during development.

**Final validation checklist**

| Layer | What it does | How we implemented it |
| --- | --- | --- |
| **Size limit** | Prevent memory exhaustion | `http.MaxBytesReader` |
| **JSON syntax** | Catch malformed JSON | `json.Decoder.Decode` error |
| **Required fields** | Ensure mandatory data is present | Check for empty strings |
| **Type conversion** | Convert strings to numbers | `strconv.Atoi` with error handling |
| **Business rules** | Validate formats, ranges, lengths | Custom validation functions |
| **Structured errors** | Return machine-readable errors | `errorResponse` with `details` array |
| **Multiple errors** | Return all problems at once | Collect errors in a slice |

This is a complete, production-grade validation approach.

type contextKey string

const requestIDKey contextKey = "request_id"

var logger *slog.Logger

type validationError struct {
	Field   string `json:"field"`
	Message string `json:"message"`
}

type errorResponse struct {
	Error   string            `json:"error"`
	Message string            `json:"message"`
	Details []validationError `json:"details,omitempty"`
}

func main() {

	// Initialize structured JSON logger
	logger = slog.New(slog.NewJSONHandler(os.Stdout, nil))

	mux := http.NewServeMux()
	mux.HandleFunc("GET /{$}", homeHandler)
	mux.HandleFunc("GET /health", healthHandler)
	mux.HandleFunc("GET /api/hello", helloHandler)
	mux.HandleFunc("POST /api/users", createUserHandler)
	mux.HandleFunc("GET /api/search", searchHandler)

	handler := recoverMiddleware(loggingMiddleware(mux))

	server := &http.Server{
		Addr:         ":8080",
		Handler:      handler,
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 10 * time.Second,
	}

	// serverErr carries fatal startup errors (e.g. port already in use)
	// from the server goroutine back to main.
	serverErr := make(chan error, 1)

	go func() {
		log.Println("server starting on :8080")
		// http.ErrServerClosed is the expected result of a graceful Shutdown,
		// so we only report real errors.
		if err := server.ListenAndServe(); err != nil && err != http.ErrServerClosed {
			serverErr <- err
		}
	}()

	// Wait for either a shutdown signal or a startup failure.
	sigChan := make(chan os.Signal, 1)
	signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)

	select {
	case err := <-serverErr:
		log.Fatalf("server failed to start: %v", err)
	case sig := <-sigChan:
		log.Printf("received signal %v, shutting down", sig)
	}

	// Graceful drain, capped at 10 seconds.
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	if err := server.Shutdown(ctx); err != nil {
		log.Printf("forced shutdown: %v", err)
		os.Exit(1)
	}

	log.Println("graceful shutdown complete")
}

func writeJSON(w http.ResponseWriter, status int, data any) {

func recoverMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("recovered from panic: %v\n%s", rec, debug.Stack())

				writeJSON(w, http.StatusInternalServerError, map[string]string{
					"error": "Internal Server Error",
				})
			}
		}()

		next.ServeHTTP(w, r)
	})
}

func loggingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// 1. Generate request ID
		id, err := newRequestID()
		if err != nil {
			id = "unknown" // Fallback if random generation fails
		}

		// NEW: Return the ID to the client
		w.Header().Set("X-Request-ID", id)

		// 2. Attach to context
		ctx := context.WithValue(r.Context(), requestIDKey, id)
		r = r.WithContext(ctx)

		// 3. Wrap the response writer to capture status code
		rw := &responseWriter{ResponseWriter: w, status: http.StatusOK}

		// 4. Log the start
		start := time.Now()
		logger.Info("request started",
			"request_id", id,
			"method", r.Method,
			"path", r.URL.Path,
		)

		// 5. Execute the actual handler
		next.ServeHTTP(rw, r)

		// 6. Log the completion
		duration := time.Since(start)
		logger.Info("request finished",
			"request_id", id,
			"status", rw.status,
			"duration_ms", duration.Milliseconds(),
		)
	})
}

func newRequestID() (string, error) {
	b := make([]byte, 16)

	if _, err := rand.Read(b); err != nil {
		return "", err
	}

	return hex.EncodeToString(b), nil
}
func createUserHandler(w http.ResponseWriter, r *http.Request) {
	const maxBodySize = 1 << 20 // 1 MB
	r.Body = http.MaxBytesReader(w, r.Body, maxBodySize)

	var user struct {
		Name  string `json:"name"`
		Email string `json:"email"`
	}

	decoder := json.NewDecoder(r.Body)
	decoder.DisallowUnknownFields()

	if err := decoder.Decode(&user); err != nil {
		writeJSON(w, http.StatusBadRequest, errorResponse{
			Error:   "invalid_json",
			Message: "Request body contains unknown fields",
		})
		return
	}

	// Collect all validation errors
	var errors []validationError

	if user.Name == "" {
		errors = append(errors, validationError{
			Field:   "name",
			Message: "Name is required",
		})
	} else if len(user.Name) < 2 {
		errors = append(errors, validationError{
			Field:   "name",
			Message: "Name must be at least 2 characters",
		})
	}

	if user.Email == "" {
		errors = append(errors, validationError{
			Field:   "email",
			Message: "Email is required",
		})
	} else if !isValidEmail(user.Email) {
		errors = append(errors, validationError{
			Field:   "email",
			Message: "Email format is invalid",
		})
	}

	// If there are validation errors, return them
	if len(errors) > 0 {
		writeJSON(w, http.StatusBadRequest, errorResponse{
			Error:   "validation_failed",
			Message: "Request validation failed",
			Details: errors,
		})
		return
	}

	// Success case
	log.Printf("created user: %s (%s)", user.Name, user.Email)
	writeJSON(w, http.StatusCreated, map[string]string{
		"message": "User created",
		"name":    user.Name,
		"email":   user.Email,
	})
}
func isValidEmail(email string) bool {
	return strings.Contains(email, "@")
}

func searchHandler(w http.ResponseWriter, r *http.Request) {
	query := r.URL.Query()

	// Collect validation errors
	var errors []validationError

	// Required parameter: q
	q := query.Get("q")
	if q == "" {
		errors = append(errors, validationError{
			Field:   "q",
			Message: "Search query is required",
		})
	}

	// Optional parameter: page (default 1, must be positive)
	pageStr := query.Get("page")
	page := 1
	if pageStr != "" {
		p, err := strconv.Atoi(pageStr)
		if err != nil {
			errors = append(errors, validationError{
				Field:   "page",
				Message: "Page must be a number",
			})
		} else if p < 1 {
			errors = append(errors, validationError{
				Field:   "page",
				Message: "Page must be at least 1",
			})
		} else {
			page = p
		}
	}

	// Optional parameter: limit (default 10, must be 1-100)
	limitStr := query.Get("limit")
	limit := 10
	if limitStr != "" {
		l, err := strconv.Atoi(limitStr)
		if err != nil {
			errors = append(errors, validationError{
				Field:   "limit",
				Message: "Limit must be a number",
			})
		} else if l < 1 || l > 100 {
			errors = append(errors, validationError{
				Field:   "limit",
				Message: "Limit must be between 1 and 100",
			})
		} else {
			limit = l
		}
	}

	// Return validation errors if any
	if len(errors) > 0 {
		writeJSON(w, http.StatusBadRequest, errorResponse{
			Error:   "validation_failed",
			Message: "Query parameter validation failed",
			Details: errors,
		})
		return
	}

	// Success: return the parsed parameters
	writeJSON(w, http.StatusOK, map[string]any{
		"query": q,
		"page":  page,
		"limit": limit,
	})
}
