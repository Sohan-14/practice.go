**P1 — Graceful Shutdown**

## **Why this one first?**

- It's priority #1 (availability)
- It teaches three concepts you'll reuse forever: **signals**, **context**, and the **server lifecycle**
- It sets up the pattern for almost every later fix (logging, metrics, etc. all hook into this lifecycle)

| Module | What you'll learn |

# **Module 1: Reproduce the Problem**

**Goal:** Right now the bug is *invisible* because requests finish too fast. We'll add a deliberately slow endpoint so we can **watch** the server murder an in-flight request.

**Step 1 — Add a `/slow` endpoint**

```go
// Register it with the other routes:
mux.HandleFunc("GET /slow", slowHandler)

// The handler:
func slowHandler(w http.ResponseWriter, r *http.Request) {
    log.Println("⏳ slow request STARTED")
    time.Sleep(5 * time.Second) // pretend this is a real 5s job
    fmt.Fprintln(w, "slow request completed ✅")
    log.Println("🏁 slow request FINISHED")
}
```

Add this to your `main.go`

**Step 2 — The experiment**

Open **two terminals**.

**Terminal A** — run the server:

```bash
go run main.go
```

**Terminal B** — hit the slow endpoint:

```bash
curl http://localhost:8080/slow
```

**Step 3 — The kill**

While `curl` in Terminal B is **still waiting** (within those 5 seconds), go to **Terminal A** and press **`Ctrl+C`**.

 **Observe what happens**

- **Terminal B (curl):** the request dies → you get `curl: (52) Empty reply from server` or a connection error. **No response. No message. Nothing.**
- **Terminal A:** the server exits immediately. You'll see `⏳ slow request STARTED` but **never** `🏁 slow request FINISHED`.

 **Why this is a real problem**

`ListenAndServe()` gets torn down instantly. The open connection is **severed mid-way**, so the client receives nothing.

In production, this happens on **every single deploy or restart**:

*Every user whose request was being processed at that exact moment gets an error.*

That's why "graceful" means: **stop accepting NEW requests, but FINISH the ones already in progress.**

# **Module 2: OS Signals**

#### The concept

When you press **`Ctrl+C`**, your terminal doesn't kill the program directly. It asks the **operating system** to send your program a **signal** — an asynchronous "tap on the shoulder" notification.

By default, that signal kills the process immediately. **But** a program can choose to *intercept* it and decide what to do instead.

> That interception is the entire trick behind graceful shutdown.
>

#### **The two signals that matter**

| Signal | Trigger | Meaning |
| --- | --- | --- |
| SIGINT | You press `Ctrl+C` | "Interrupt" — local/dev |
| SIGTERM | `kill`, **Docker**, **Kubernetes** | "Please terminate" — **production** |

**Key production insight:** when Kubernetes/Docker stops your container, it sends **`SIGTERM`**, not Ctrl+C. So a real server must handle **both**. This is the difference between "works locally" and "survives in production."

**The Go tools**

- Package **`os/signal`** — lets you receive signals on a channel.
- **`signal.Notify(ch, ...)`** — tells the OS: *"route these signals into this channel instead of killing me."*

Graceful shutdown needs a  rule

*Finish the in-flight work… but don't wait forever. Force-quit after 10 seconds.*

# **Module 3: `context.Context` — Deadlines & Cancellation**

### The concept

A **`context.Context`** is an object you pass around that carries:

- a **deadline** ("cancel after X seconds"), and/or
- a **cancellation signal** ("stop now"), and/or
- request-scoped values

The part we care about: **a context can be cancelled, and you can detect it.**

**The core API (only what we need)**

| Thing | What it does |
| --- | --- |
| `context.Background()` | The root/empty context — where you start |
| context.WithTimeout(parent, d) | Returns a context that **auto-cancels after duration `d`** |
| `ctx.Done()` | A channel that **closes when the context is cancelled** |
| ctx.Err() | *Why* it was cancelled (`context.DeadlineExceeded` or `context.Canceled`) |
| cancel() | A cleanup function returned by `WithTimeout` — call it (`defer`) to free resources |

# **Module 4: Restructure — Run the Server in a Goroutine**

### The problem

`ListenAndServe()` **blocks** — it grabs `main` and never lets go. So `main` can't *also* be waiting for a signal. It's stuck doing one thing.

We need `main` to do **two things at once**:

1. Serve requests
2. Listen for the shutdown signal

### The answer: a **goroutine**

The Go feature for "do this in the background" is a **goroutine**. You launch one with the `go` keyword:

```go
go func() {
    // this runs in the background, concurrently
}()
```

It's a lightweight concurrent task. `go f()` starts `f` and **immediately moves on** — it doesn't wait.

**Before vs. after**

```markdown
BEFORE (broken for our needs):
  main ──> ListenAndServe() ━━━━━ blocks forever, nothing else possible

AFTER:
  goroutine ──> ListenAndServe() ━━━━━ serves requests in background
  main ────────> wait for signal ━━━━━ free to catch Ctrl+C / SIGTERM
```

Two things, at once.

**Restructured main.go**

```go
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	mux := http.NewServeMux()

	// Register routes
	mux.HandleFunc("GET /{$}", homeHandler)
	mux.HandleFunc("GET /health", healthHandler)
	mux.HandleFunc("GET /api/hello", helloHandler)
	mux.HandleFunc("GET /slow", slowHandler)

	addr := ":8080"
	server := &http.Server{
		Addr:         addr,
		Handler:      mux,
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 10 * time.Second,
	}

	// NEW: run the server in the background
	go func() {
		log.Println("🚀 server starting on http://localhost:8080")
		if err := server.ListenAndServe(); err != nil {
			log.Printf("server error: %v", err)
		}
	}()

	// NEW: meanwhile, main waits for a shutdown signal
	sigChan := make(chan os.Signal, 1)
	signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)

	sig := <-sigChan // blocks here until Ctrl+C / SIGTERM
	log.Printf("📴 received %v — shutting down...", sig)
}

// slowHandler take time to respond, simulating a long-running process
func slowHandler(w http.ResponseWriter, r *http.Request) {
	log.Println("⏳ slow request STARTED")
	time.Sleep(5 * time.Second) // pretend this is a real 5s job
	fmt.Fprintln(w, "slow request completed ✅")
	log.Println("🏁 slow request FINISHED")
}

// homeHandler returns a welcome message
func homeHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "Welcome to my Go HTTP server!")
	fmt.Fprintln(w, "Try: /health or /api/hello?name=World")
}

// healthHandler returns server health status
func healthHandler(w http.ResponseWriter, r *http.Request) {
	writeJSON(w, http.StatusOK, map[string]string{
		"status": "ok",
	})
}

// helloHandler returns a personalized greeting
func helloHandler(w http.ResponseWriter, r *http.Request) {
	name := r.URL.Query().Get("name")
	if name == "" {
		name = "World"
	}
	writeJSON(w, http.StatusOK, map[string]string{
		"message": fmt.Sprintf("Hello, %s!", name),
	})
}

// writeJSON is a helper to send JSON responses
func writeJSON(w http.ResponseWriter, status int, data any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	json.NewEncoder(w).Encode(data)
}

```

**What changed**

| Change | Why |
| --- | --- |
| `go func() { ListenAndServe() }()` | Server now runs **in the background**, so it doesn't block `main`. |
| `signal.Notify(...)` + `<-sigChan` | `main` is now **free** to wait for the shutdown signal. |

**Checkpoint**

- Run it: `go run main.go`
- Confirm it still serves: `curl http://localhost:8080/` ✅
- Press **`Ctrl+C`**.

You should now see:

```bash
🚀 server starting on http://localhost:8080
^C
📴 received interrupt — shutting down...
```

# **Module 5: Graceful Stop — `server.Shutdown(ctx)`**

**The core concept: two ways to stop a server**

| Method | Behavior |
| --- | --- |
| `server.Close()` | 🔪 **Brutal.** Kills the listener and drops all connections *instantly*. In-flight requests die. |
| `server.Shutdown(ctx)` | 🕊️ **Graceful.** Stops accepting *new* requests, then **waits for in-flight ones to finish** — but honors a deadline. |

`Close()` is what effectively happened before (everything died). `Shutdown(ctx)` is what we want.

**How `Shutdown` works (internally)**

1. Close the listener → **no new requests** get in.
2. Wait for active requests to finish.
3. **Race against `ctx`:**
    - All drained before the deadline → returns `nil` ✅
    - Deadline hits first → returns `ctx.Err()` (`context deadline exceeded`) ⚠️

**Fill in the drain logic**

add to the end of the main

```go
// NEW: graceful drain, capped at 10 seconds
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	if err := server.Shutdown(ctx); err != nil {
		log.Printf("⚠️ forced shutdown: %v", err)
	} else {
		log.Println("✅ graceful shutdown complete")
	}
```

**Line-by-line**

| LIne | What is does |
| --- | --- |
| `context.WithTimeout(..., 10*time.Second)` | The **deadline**: "give it at most 10s to drain." |
| defer cancel() | Hygiene — frees the timer resources when we're done. |
| server.Shutdown(ctx) | Gracefully stops: no new requests, waits for active ones, bounded by `ctx`. |
| `if err != nil` → `⚠️ forced` | Deadline hit before draining finished → not graceful, but we **don't hang forever**. |
| `else` → `✅ graceful` | Everything drained within 10s. Clean exit. |

Did the server finish draining before the 10s deadline

**Checkpoint — the happy path**

- Run it: `go run main.go`
- Make sure **no request is in flight**, then press `Ctrl+C`.

You should see:

```go
📴 received interrupt — shutting down...
✅ graceful shutdown complete
```

# **Module 6: Verify — Prove Graceful Shutdown Actually Works**

So far, we have:

- caught shutdown signals
- stopped the server using `Shutdown(ctx)`
- added a shutdown deadline

But we must prove this:

If a request is already running, does it finish after we press `Ctrl+C`?

**Test 1: In-flight request should survive**

Keep your shutdown timeout as:

```go
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
```

Your `/slow` handler should still sleep for 5 seconds:

```go
time.Sleep(5 * time.Second)
```

So:

```go
request duration: 5s
shutdown grace:  10s
```

The request should finish before the shutdown deadline.

**Step 1: Start the server**

Terminal A:

```go
go run main.go
```

You should see:

```go
🚀 server starting on http://localhost:8080
```

**Step 2: Start a slow request**

Terminal B:

```go
curl http://localhost:8080/slow
```

Server logs should show:

```go
⏳ slow request STARTED
```

Now curl is waiting.

**Step 3: Press `Ctrl+C` while curl is still waiting**

Go back to Terminal A and press:

```go
Ctrl+C
```

Expected result

Terminal B should now receive:

```go
slow request completed ✅
```

That means the in-flight request survived.

**Terminal A should show something like:**

```go
⏳ slow request STARTED
📴 received interrupt — shutting down...
server error: http: Server closed
🏁 slow request FINISHED
✅ graceful shutdown complete
```

The exact order may vary slightly, but the important part is:

```go
🏁 slow request FINISHED
✅ graceful shutdown complete
```

**Why it works now**

Before:

```markdown
Ctrl+C
  ↓
process exits immediately
  ↓
active connection dies
  ↓
client gets socket hang up
```

After:

```markdown
Ctrl+C
  ↓
signal is caught
  ↓
server.Shutdown(ctx) is called
  ↓
server stops accepting new requests
  ↓
existing /slow request is allowed to finish
  ↓
server exits cleanly
```

This is graceful shutdown.

**Test 2: New requests should be rejected during shutdown**

This is also important.

Graceful shutdown does **not** mean:

> "Keep accepting everything."
>

It means:

> "Stop accepting new work, but finish existing work."
>

**Test 3: Deadline should force shutdown if request takes too long**

Change this:

```go
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
```

to this temporarily:

```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
```

Test again:

Server logs should show:

```go
📴 received interrupt — shutting down...
⚠️ forced shutdown: context deadline exceeded
```

## Important lesson

Graceful shutdown is not infinite waiting.

# **Module 7: Polish — Make It Professional**

Restructured main.go:

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"log"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /{$}", homeHandler)
	mux.HandleFunc("GET /health", healthHandler)
	mux.HandleFunc("GET /api/hello", helloHandler)

	server := &http.Server{
		Addr:         ":8080",
		Handler:      mux,
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 10 * time.Second,
	}

	// serverErr carries fatal startup errors (e.g. port already in use)
	// from the server goroutine back to main.
	serverErr := make(chan error, 1)

	go func() {
		log.Println("server starting on :8080")
		// http.ErrServerClosed is the expected result of a graceful Shutdown,
		// so we only report real errors.
		if err := server.ListenAndServe(); err != nil && err != http.ErrServerClosed {
			serverErr <- err
		}
	}()

	// Wait for either a shutdown signal or a startup failure.
	sigChan := make(chan os.Signal, 1)
	signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)

	select {
	case err := <-serverErr:
		log.Fatalf("server failed to start: %v", err)
	case sig := <-sigChan:
		log.Printf("received signal %v, shutting down", sig)
	}

	// Graceful drain, capped at 10 seconds.
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	if err := server.Shutdown(ctx); err != nil {
		log.Printf("forced shutdown: %v", err)
		os.Exit(1)
	}

	log.Println("graceful shutdown complete")
}

func homeHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "Welcome to my Go HTTP server!")
	fmt.Fprintln(w, "Try: /health or /api/hello?name=World")
}

func healthHandler(w http.ResponseWriter, r *http.Request) {
	writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
}

func helloHandler(w http.ResponseWriter, r *http.Request) {
	name := r.URL.Query().Get("name")
	if name == "" {
		name = "World"
	}
	writeJSON(w, http.StatusOK, map[string]string{
		"message": fmt.Sprintf("Hello, %s!", name),
	})
}

func writeJSON(w http.ResponseWriter, status int, data any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	json.NewEncoder(w).Encode(data)
}

```
